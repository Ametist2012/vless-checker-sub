# VLESS Checker

Сервис берёт VLESS-конфиги из подписок, **по-настоящему подключается** к каждому через xray, отбирает лучшие
и раздаёт их как подписки для [Happ](https://www.happ.su). Настраивается через веб-панель.

## Возможности

- **Группы подписок** (например, белые и чёрные списки): свои источники, своя выдача, свой размер (по умолчанию 55).
- **Реальная проверка** выбранными способами: пинг напрямую, пинг через подключение, загрузка сайтов, speedtest.
- **Фильтр стран** по реальному IP выхода, а не по названию конфига.
- **Рейтинг с историей**: стабильность за последние 12 часов влияет на место в подписке.
- **Для Happ**: зашифрованная ссылка `happ://crypt5/…`, QR-код, маршрутизация `happ://routing/…` в подписке,
  режим «только Happ».
- **Безопасность**: панель по секретному адресу и под паролем, у каждой группы своя секретная ссылка, которую можно
  сменить, если она утекла.
- **Выключатель**: останавливает проверки и выдачу подписок, не трогая панель.
- **Меню на сервере** `v-chk`: адрес панели, логин и пароль, состояние, перезапуск, лог.

## Как устроено

| Часть | Что делает |
|---|---|
| `src/VlessCheck.Core` | Общая библиотека: разбор vless, конфиги xray, проверки, рейтинг, SQLite, вход |
| `src/VlessCheck.Checker` | Воркер (systemd `vlesscheck-checker`): проверяет группы по расписанию или по кнопке |
| `src/VlessCheck.Api` | ASP.NET Core (systemd `vlesscheck-api`, `127.0.0.1:8787`): API, панель, выдача подписок |
| `web` | Панель на React + Vite, собирается в `src/VlessCheck.Api/wwwroot` |
| `deploy` | Скрипты выкладки и настройки сервера, systemd-юниты, шаблон nginx, меню `v-chk` |

Процессы общаются через общую базу `/opt/vlesscheck/data/vlesscheck.db` и файлы статуса рядом с ней.

**Цикл проверки группы:**
1. Скачивает подписки группы (обычные и base64), оставляет `vless://` и убирает дубли.
2. Отсеивает серверы с закрытым портом.
3. Пачками поднимает xray и проверяет каждый конфиг выбранными способами («Настройки → Как проверять»):
   - **пинг напрямую**: время TCP-подключения к серверу;
   - **пинг через подключение**: «реальная задержка» через сам конфиг (`generate_204`), первая неудача — отбраковка;
   - **загрузка сайтов**: открывает выбранные сайты как браузер; не открылся ни один — отбраковка;
   - **speedtest**: скорость скачивания у лучших по задержке (на части серверов его блокируют).

   Нужен хотя бы «пинг через подключение» или «сайты». Всегда проверяется IP выхода через `cloudflare.com/cdn-cgi/trace`:
   что трафик реально идёт через сервер, и страна для фильтра.
4. Убирает исключённые страны.
5. Оценка 0–100: стабильность 40 + 60 поровну между включёнными способами проверки.
6. Берёт топ-N (сначала не больше M на сервер, потом добирает) и публикует подписку.

Если ни один конфиг не прошёл, остаётся прошлая подписка.

## Адреса

Всё живёт под одним префиксом на вашем сайте (`PANEL_PREFIX`, по умолчанию `checker`):

| Адрес | Что |
|---|---|
| `https://<сайт>/checker/<секрет>/` | панель со страницей входа; секрет меняется в «Настройки → Адрес панели» |
| `https://<сайт>/checker/sub/<токен>/<группа>` | подписка группы (не зависит от секрета панели) |
| всё остальное под `/checker/` | 404 |

## Установка на сервер

Одной командой на сервере (Ubuntu/Debian с systemd, от root). Репозиторий приватный, поэтому нужен GitHub-токен
на чтение: Settings → Developer settings → Fine-grained tokens, доступ только к `vless-checker-sub`,
право **Contents: Read-only**.

```bash
export GITHUB_TOKEN=github_pat_…
```

```bash
bash <(curl -fsSL -H "Authorization: Bearer $GITHUB_TOKEN" https://raw.githubusercontent.com/Ametist2012/vless-checker-sub/main/install.sh)
```

Токен нужен только на время установки или обновления, на сервере он не сохраняется.

Установщик скачивает готовую сборку из GitHub Releases (x64 или arm64, .NET на сервере не нужен) и спрашивает,
куда подключить панель:
- **к существующему HTTPS-сайту nginx**: выбираете из списка, в его конфиг добавится одна строка `include`
  (с резервной копией и откатом, если `nginx -t` не проходит);
- **к новому сайту с сертификатом Let's Encrypt**: указываете домен, A-запись которого смотрит на сервер;
  установщик поставит nginx и certbot, получит сертификат и включит автопродление, корень сайта отдаёт 404;
- **без nginx**: панель только на `127.0.0.1:8787`, подключите её к своему прокси сами.

Затем ставит xray, создаёт пользователя `vlesscheck`, systemd-сервисы, меню `v-chk` и показывает адрес панели,
логин и пароль. База — SQLite, ставить ничего не нужно. Группы «Белые» и «Чёрные» создаются пустыми,
источники подписок добавляются в панели.

| Команда | Что делает |
|---|---|
| та же команда ещё раз | обновление до последнего релиза без вопросов, данные и настройки сохраняются |
| `… install.sh) --version v1.2.0` | установка конкретной версии |
| `… install.sh) uninstall` | удаление; базу удаляет только по отдельному подтверждению |
| `sudo v-chk` | меню на сервере: адрес панели, логин и пароль, сброс пароля, состояние, лог |

Если установка или обновление падает на полпути, прежняя версия запускается обратно.
Ограничения, чтобы не мешать другим сервисам на сервере: API до 160 МБ, проверка (вместе с её xray) до 300 МБ RAM,
низкий приоритет CPU и диска.

**Безопасность входа:** пароль хранится как PBKDF2-хеш, сессия — подписанная cookie (HttpOnly, Secure, SameSite=Strict,
30 дней); после 5 неверных паролей вход с одного IP блокируется на минуту. Забытый пароль сбрасывается в `v-chk`.

## Релизы

```bash
git tag v1.0.0 && git push origin v1.0.0
```

GitHub Actions (`.github/workflows/release.yml`) собирает архивы под linux-x64 и linux-arm64 и публикует их в Releases
вместе с `install.sh`. Собрать архив локально: `./deploy/package.sh linux-x64`.

**Выкладка из исходников на свой сервер** (без релиза): скопируйте `deploy/deploy.env.example` в `deploy/deploy.env`,
заполните (файл в git не попадает) и запустите `./deploy/deploy.sh` — он соберёт архив и поставит его тем же `install.sh`.

## Локальный запуск

Нужны .NET 10 SDK, Node.js и xray (`brew install xray`).

```bash
cd web && npm install && npm run build && cd ..
```

```bash
dotnet run --project src/VlessCheck.Api -- --urls http://127.0.0.1:8788
```

```bash
dotnet run --project src/VlessCheck.Checker
```

При первом запуске API печатает в лог логин и пароль, а секрет адреса панели хранится в базе (`./data`,
переменная `VLESSCHECK_DATA`). Диагностика одной ссылки:

```bash
dotnet run --project src/VlessCheck.Checker -- probe "vless://…"
```

## Важно

Результаты зависят от сети, из которой идёт проверка: ставьте сервис в той стране, откуда будете подключаться.
Мобильные «белые списки» операторов так не проверить: для этого нужна проверка с мобильной SIM.
